The Big Question

Can a machine price a neighborhood?

  • Given what the Census knows about a NC neighborhood — income, population, households, location, housing age — can we predict its median home value?
  • One row = one census block group (~600–3,000 people).

The Hypothesis

Draw the finish line before you build

The boss fight of this module isn't code — it's deciding what "done" means in advance, so you don't polish forever. We committed to two measurable signals, in writing.

The metric is the ruler. "Good enough" is the line you draw on it. A charter needs both.

Definition of "good enough"

  • Beat the naive baseline — do better than just predicting the statewide average.
  • Find the turnaround epoch — the point where validation error stops improving.
Both are falsifiable. Both were written down on day one. Spoiler: we hit both.
Materials & Method

The model, the ruler, the referee

🧠 The Model

Feed-forward net: 2 hidden layers × 64 ReLU units, one linear output. Keras 3 on the PyTorch backend. Small on purpose — the textbook's Housing shape.

📏 The Ruler (MAE)

Mean Absolute Error, in dollars. "On average, how many dollars are we off?" Human-legible — you can feel a dollar error.

⚖️ The Referee (k-fold)

K-fold cross-validation: rotate which slice is held out, average the results. Honest error, not lucky-split error. A separate test set is the final exam.

Lab Discipline

The One Change Rule

  • Every experiment changed exactly one thing, then re-ran the whole pipeline.
  • Held fixed: same data, same split seed, same weight-init seed, same 50 epochs.
  • Every run writes a timestamped bundle (log + plots) — nothing overwrites anything.
  • This is why the flat result later is a finding, not noise.
Change three things and the number moves? You've learned nothing. Change one knob per run — and you can trust the answer.

The Envelope, Please

Nothing helped — and that's the finding

Validation MAE across all five runs — the shaded band is the noise floor
Five runs, one knob each. Line them up and they're all the same height. You cannot make this model better by making it bigger. The negative result is the discovery — so the real question is why not?
The Diagnosis

Why bigger didn't win:
MSE's long tail

  • RMSE ≈ 1.6 × MAE, stably. RMSE squares errors first — so a few big misses dominate.
  • Those misses are the rare, expensive neighborhoods.
  • Tail compression: the worst ~$1.04M block was guessed lower as capacity grew: $427K → $400K → $393K.
  • An MSE-trained model plays it safe on rare high-value homes — and a bigger one plays it safer.
MAE vs RMSE — the gap is the fingerprint of a few large misses

Conclusion

The ceiling is the signal, not the size

What we set out to do

  • Beat the baseline — ~47% lower error than the mean.
  • Found the turnaround epoch — ~12–13.

What we learned

  • The model is not capacity-limited — width and depth both failed.
  • The ceiling = signal in 7 features + MSE's tail compression, not model size.
To do better we'd change the signal (features / data) or the loss — not add layers. That's a far more useful conclusion than "we added layers and the number went down."
Scope Guard

What we deliberately did not do

A science-fair board should say what it isn't. Over-scoping is the #1 way these projects die. We wrote the guardrails on day one and held the line.

That discipline is why there's a finished project to present.
  • No general ACS cleaning pipeline — only fixed this file's known bad rows.
  • No re-deriving features from the raw Census API — used the pre-built CSV.
  • No deployment, no UI — model + evaluation only.

Reflection

What the process taught us

  • The One Change Rule turned a flat result into a trustworthy one.
  • Timestamped runs → every claim on this board is reproducible from a stamp.
  • The biggest single win was data cleaning, not modeling.
  • "Define good enough first" stopped us chasing a bigger model forever.
🧪

The real lesson wasn't about neural networks. It was that disciplined process is what let us confidently say "bigger won't help."

Without it, five nearly-identical numbers would've looked like failure — instead of a finding.
